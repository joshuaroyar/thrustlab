Here is the most robust way to handle this using the marked library for parsing and dompurify for security (to prevent XSS attacks from hallucinated scripts).

Prerequisites
You need to install two packages: one to parse the Markdown and one to sanitize the HTML.

Bash

npm install marked dompurify
npm install -D @types/marked @types/dompurify # If using TypeScript

Implementation Options
Option 1: The "Auto-Magic" Component (Recommended)
Create a reusable Svelte component (e.g., MarkdownRenderer.svelte). This keeps your chat logic clean.

src/lib/components/MarkdownRenderer.svelte

Svelte

<script>
  import { marked } from 'marked';
  import DOMPurify from 'dompurify';

  export let content = '';

  // Reactive statement: whenever 'content' changes, re-parse and sanitize
  // We use simple HTML generation here.
  $: htmlContent = DOMPurify.sanitize(marked.parse(content));
</script>

<div class="markdown-body prose dark:prose-invert max-w-none">
  {@html htmlContent}
</div>

<style>
  /* Optional: Basic styling if you aren't using Tailwind */
  :global(.markdown-body pre) {
    background: #1e1e1e;
    padding: 1rem;
    border-radius: 8px;
    overflow-x: auto;
  }
  :global(.markdown-body code) {
    background: rgba(0,0,0,0.1);
    padding: 0.2rem 0.4rem;
    border-radius: 4px;
  }
</style>
Usage in your Chat Page:

Svelte

<script>
  import MarkdownRenderer from '$lib/components/MarkdownRenderer.svelte';
  
  let chatMessage = "Here is some **bold** text and a list:\n- Item 1\n- Item 2";
</script>

<div class="chat-bubble">
  <MarkdownRenderer content={chatMessage} />
</div>

Option 2: Handling Code Blocks (Syntax Highlighting)
Since you are using Groq/HuggingFace, your bot will likely generate code. Standard Markdown rendering will look plain. You should add highlight.js to make code blocks look like an IDE.

Install Highlight.js:

Bash

npm install highlight.js
Update the Component:

src/lib/components/MarkdownRenderer.svelte

Svelte

<script>
  import { marked } from 'marked';
  import DOMPurify from 'dompurify';
  import hljs from 'highlight.js';
  
  // Import a theme (VS Code Dark style)
  import 'highlight.js/styles/vs2015.css'; 

  export let content = '';

  // Configure marked to use highlight.js for code blocks
  const renderer = new marked.Renderer();
  
  // Custom code renderer
  renderer.code = ({ text, lang }) => {
    const validLang = !!(lang && hljs.getLanguage(lang));
    const highlighted = validLang 
      ? hljs.highlight(text, { language: lang }).value 
      : hljs.highlightAuto(text).value;
      
    return `<pre><code class="hljs ${lang || ''}">${highlighted}</code></pre>`;
  };

  marked.setOptions({ renderer });

  $: htmlContent = DOMPurify.sanitize(marked.parse(content));
</script>

<div class="prose dark:prose-invert max-w-none">
  {@html htmlContent}
</div>

Important Considerations for SvelteKit
1. Styling (Tailwind Typography) If you are using Tailwind CSS, the raw HTML generated by marked won't have styles by default (h1 will look like p).

Install the typography plugin: npm install -D @tailwindcss/typography

Add it to tailwind.config.js: plugins: [require('@tailwindcss/typography')],

Add the prose class to the container div (as shown in the code examples above).

2. Server-Side Rendering (SSR) Issue DOMPurify relies on the window object, which doesn't exist on the server. If you try to render this on the server (SSR), it might crash.

Fix: Since this is a chatbot, the messages are usually loaded on the client anyway. However, if you render initial chat history on the server, utilize isomorphic-dompurify instead of standard dompurify to handle both environments automatically.

Summary of Workflow
Groq sends the response string: "Here is a function: \n ```js \n console.log('hi') \n ```".

Svelte passes this string to MarkdownRenderer.

Marked converts it to raw HTML with <pre><code> tags.

Highlight.js (optional) injects color classes into the code tags.

DOMPurify strips out any malicious <script> tags the AI might have Hallucinated.

Svelte injects the safe HTML into the DOM.
